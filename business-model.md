# БИЗНЕС-ДОМЕН. СИСТЕМА МОНИТОРИНГА СОСТОЯНИЯ СЕРВЕРОВ

**Вариант 7**

В качестве примера работы системы массового обслуживания рассматривается вычислительная система мониторинга серверной инфраструктуры. На контролируемых серверах работают агенты мониторинга, которые формируют сообщения о текущем состоянии вычислительных ресурсов: загрузке процессора, использовании оперативной памяти, дискового пространства, состоянии сетевых соединений и возникающих ошибках.

Полученные данные поступают в центральный сервис мониторинга. Каждое сообщение формирует заявку на обработку телеметрии. Заявка должна быть проанализирована вычислительным worker-процессом, который проверяет показатели, определяет наличие аномалий и сохраняет результат для последующего отображения оператору системы.

При высокой нагрузке все worker-процессы могут оказаться заняты. В этом случае поступающие заявки помещаются в общую ограниченную очередь. Для системы мониторинга наибольшую ценность представляют наиболее свежие данные о состоянии серверов. Поэтому при переполнении очереди наиболее старая ожидающая заявка удаляется, а при освобождении вычислительного worker-процесса первой выбирается наиболее поздно поступившая заявка.

## 1. Элементы бизнес-домена

### 1.1. Источник (ИБ, ИЗ1)

Источниками являются агенты мониторинга, установленные на контролируемых серверах. Каждый агент независимо формирует новые сообщения о состоянии сервера, поэтому источник рассматривается как бесконечный.

Пример источников:

| Источник | Контролируемый объект |
|---|---|
| И1 | Web-сервер |
| И2 | Сервер базы данных |
| И3 | Файловый сервер |
| И4 | Сервер приложений |

Поступление заявок моделируется пуассоновским потоком (ИЗ1). Интервалы времени между соседними заявками имеют экспоненциальное распределение. В реальной системе это соответствует асинхронному появлению телеметрии, ошибок, скачков нагрузки и других событий.

### 1.2. Буфер (Д1ОЗ2)

Буфером является общая ограниченная очередь сообщений телеметрии, ожидающих анализа.

Если при поступлении заявки все приборы заняты, заявка помещается в конец очереди. При удалении заявки из середины или начала буфера все последующие заявки сдвигаются на одну позицию, поэтому свободных мест внутри очереди не остаётся.

Таким образом, буфер соответствует дисциплине Д1ОЗ2 — постановке заявок в порядке поступления.

### 1.3. Прибор (ПЗ2)

Приборами являются worker-процессы сервиса анализа телеметрии.

Например:

- П1 — Worker 1;
- П2 — Worker 2;
- П3 — Worker 3;
- П4 — Worker 4.

Каждый worker одновременно обслуживает одну заявку. Во время обслуживания выполняются проверка поступивших значений, поиск аномалий, определение состояния сервера и сохранение результата.

Время обслуживания моделируется равномерным распределением на интервале `[a, b]`, где `0 < a < b` (ПЗ2).

### 1.4. Дисциплина отказа (Д1ОО3)

Если в момент поступления новой заявки все приборы заняты и буфер полностью заполнен, из буфера удаляется самая старая ожидающая заявка.

Удалённая заявка считается получившей отказ, а новая заявка занимает освободившееся место.

Такое поведение соответствует предметной области: старая телеметрия постепенно теряет актуальность, поэтому при недостатке вычислительных ресурсов целесообразно сохранять более свежие данные.

Например, если буфер имеет состояние:

`[И1.3] [И2.5] [И4.2] [И1.4] [И3.7]`

и поступает новая заявка `И2.6`, то заявка `И1.3` удаляется как самая старая, а новая помещается в конец:

`[И2.5] [И4.2] [И1.4] [И3.7] [И2.6]`

### 1.5. Дисциплины постановки на обслуживание (Д2П1, Д2Б2)

**Д2Б2 — LIFO.** При освобождении прибора из буфера выбирается заявка, поступившая последней. Таким образом, при наличии очереди в первую очередь обрабатывается наиболее свежая телеметрия.

Например, из очереди

`[И2.5] [И4.2] [И1.4] [И3.7] [И2.6]`

первой будет выбрана заявка `И2.6`.

**Д2П1 — приоритет по номеру прибора.** Поиск свободного прибора каждый раз начинается с прибора с наименьшим номером. Если П1 занят, проверяется П2, затем П3 и так далее. Заявка передаётся первому найденному свободному прибору.

Например, если П1 занят, а П2 и П3 свободны, заявка будет назначена на П2.

### 1.6. Заявка

Заявкой является одно сообщение телеметрии, сформированное агентом мониторинга.

Заявка содержит:

- номер источника;
- порядковый номер заявки;
- время поступления;
- данные о состоянии сервера;
- время начала обслуживания;
- время окончания обслуживания.

Например, заявка `2.15` означает пятнадцатую заявку, сформированную источником И2.

После успешной обработки заявка покидает систему. Второй вариант выхода — отказ при переполнении буфера по дисциплине Д1ОО3.

### 1.7. Диспетчер постановки

Диспетчер постановки срабатывает при появлении новой заявки.

Его функции:

1. определить, может ли заявка быть передана на обслуживание;
2. если все приборы заняты — поставить заявку в конец буфера по Д1ОЗ2;
3. если буфер заполнен — удалить самую старую заявку по Д1ОО3;
4. поставить новую заявку на освободившееся место.

### 1.8. Диспетчер выбора

Диспетчер выбора срабатывает при наличии свободного прибора и заявок в буфере.

Его функции:

1. выбрать из буфера последнюю поступившую заявку по Д2Б2;
2. последовательно проверить приборы, начиная с П1;
3. назначить заявку первому найденному свободному прибору по Д2П1.

### 1.9. Отображение результатов (ОР1, ОД1)

В автоматическом режиме используется ОР1 — сводная таблица результатов.

Для каждого источника отображаются:

- количество сгенерированных заявок;
- количество отказов;
- вероятность отказа;
- среднее время ожидания;
- среднее время обслуживания;
- среднее время пребывания заявки в системе;
- дисперсия времени ожидания;
- дисперсия времени обслуживания.

Для каждого прибора отображается коэффициент использования.

В пошаговом режиме используется ОД1 — календарь событий, буфер и текущее состояние системы.

На каждом шаге отображаются:

- текущее модельное время;
- ближайшее особое событие;
- содержимое буфера;
- состояние каждого прибора;
- выбранная заявка;
- результат применения Д2Б2 и Д2П1;
- количество сгенерированных и отклонённых заявок.
