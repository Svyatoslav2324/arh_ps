# МАППИНГ. СИСТЕМА МОНИТОРИНГА СОСТОЯНИЯ СЕРВЕРОВ

**Вариант 7: ИБ ИЗ1 ПЗ2 Д1ОЗ2 Д1ОО3 Д2П1 Д2Б2 ОР1 ОД1**

| Элемент СМО | Сущность бизнес-домена | Назначение |
|---|---|---|
| Источник (ИБ) | Агент мониторинга на сервере | Формирует бесконечный поток заявок с телеметрией о состоянии сервера. |
| Закон генерации (ИЗ1) | Асинхронное появление телеметрии и событий | Поступление заявок моделируется пуассоновским потоком; интервалы между заявками имеют экспоненциальное распределение. |
| Заявка | Сообщение телеметрии о состоянии сервера | Единица работы системы анализа. Содержит источник, номер заявки, время поступления и измеренные показатели. |
| Буферная память (Д1ОЗ2) | Общая ограниченная очередь телеметрии | Хранит заявки, которые не могут быть сразу обработаны. Новые заявки ставятся в конец очереди; при удалении заявки последующие сдвигаются. |
| Прибор (ПЗ2) | Worker-процесс анализа телеметрии | Обрабатывает одну заявку: проверяет показатели, обнаруживает аномалии и сохраняет результат. Время обслуживания имеет равномерное распределение `[a, b]`. |
| Диспетчер постановки | Алгоритм приёма новой телеметрии | Принимает новую заявку, отправляет её на обслуживание либо помещает в буфер; при переполнении применяет дисциплину отказа. |
| Дисциплина отказа (Д1ОО3) | Удаление самой старой телеметрии | Если буфер заполнен, самая старая ожидающая заявка получает отказ и удаляется, а новая занимает её место. |
| Диспетчер выбора | Алгоритм назначения заявки worker-процессу | При освобождении прибора выбирает заявку из буфера и назначает её свободному worker-процессу. |
| Выбор заявки (Д2Б2) | Обработка наиболее свежей телеметрии | Используется LIFO: первой выбирается заявка, поступившая в буфер последней. |
| Выбор прибора (Д2П1) | Фиксированный приоритет worker-процессов | Поиск свободного прибора каждый раз начинается с П1; используется свободный прибор с минимальным номером. |
| Отказ | Устаревшее сообщение телеметрии, удалённое из очереди | Заявка покидает систему без обработки при переполнении буфера. |
| Обслуживание | Анализ состояния сервера | Worker проверяет значения, ищет аномалии, рассчитывает состояние сервера и сохраняет результат. |
| Выход из системы | Завершённая или отклонённая заявка | После обслуживания заявка покидает систему; при отказе по Д1ОО3 также удаляется из системы. |
| Отображение результатов (ОР1) | Сводная таблица статистики | Показывает количество заявок, отказы, вероятность отказа, времена ожидания/обслуживания/пребывания и коэффициенты использования приборов. |
| Отображение динамики (ОД1) | Календарь событий, буфер и состояние приборов | В пошаговом режиме показывает текущее событие, модельное время, очередь, занятость worker-процессов и результат диспетчеризации. |

## Краткая схема соответствия

```text
Агенты мониторинга
И1, И2, И3, ..., Иn
        |
        v
Диспетчер постановки
Д1ОЗ2 + Д1ОО3
        |
        v
Ограниченный буфер
        |
        v
Диспетчер выбора
Д2Б2 + Д2П1
        |
        v
Worker-процессы
П1, П2, ..., Пm
        |
        v
Результат анализа
```

Основной смысл выбранного маппинга состоит в том, что для мониторинга инфраструктуры свежая телеметрия важнее устаревшей. Поэтому дисциплины варианта естественно интерпретируются следующим образом: самая старая заявка вытесняется при переполнении очереди, а самая новая заявка обслуживается первой.
